Technical Roles in Web3 技术岗位全景

我的学习与错题新手路线课后小测

记录仅保存在当前浏览器；已读不等于已经掌握。

Web3 技术岗位分为“链上原生”与“Web2.5 融合”两类：前者包括智能合约工程师（用 Solidity、Rust 或 Move 编写协议逻辑，见本站「Smart Contracts & Token Approvals 智能合约与代币授权」一课）、安全审计师（用静态分析、模糊测试与人工审阅排查重入、权限及预言机操纵漏洞）及底层协议与零知识证明（ZK）工程师；后者包括 Web3 前端工程师（用 Viem、Wagmi 等处理钱包连接与交易状态）及后端与链上数据索引工程师（维护节点调用并解析链上事件日志）。因合约部署后难篡改且直接掌管资金池，工程上极度强调测试覆盖率、Gas 优化与防御性编程。

定义围绕区块链协议、智能合约、安全审计与去中心化应用前后端开发所形成的技术职业体系，分为链上原生研发与 Web2.5 融合工程两大路径。
第一次看交易图？先认识这些词
K线、蜡烛图是什么？
一根像蜡烛的小图形，记录一段时间的开盘价、最高价、最低价和收盘价。选择“1天”，一根就是一天；选择“1小时”，一根就是一小时。
“周期/长度14”是什么意思？
通常是用最近14根K线来计算，不一定是14天。在1小时图上，就是最近14根一小时K线。
主图、副图在哪？
主图是显示价格的大图。副图是下面单独的一小块图，数字的单位可能和价格完全不同，不能直接比大小。
“信号”是什么意思？
只是一个值得留意的现象，例如两条线交叉了；不是保证涨跌，也不会因为你添加指标就自动下单。
趋势、动量、波动，有什么不同？
趋势看一段时间的大方向；动量看涨跌推进得快不快、有多用力；波动看价格折腾的幅度有多大。跌得很快可以是下跌动量强，绝不是只有上涨才叫强。
交叉、背离、确认是什么意思？
交叉是两条线穿过彼此；背离是价格和指标没有一起走出同样的新高或新低；确认通常是等这根K线结束或等后面几根走完，才能把现象认定下来。指标的标记画在过去，不代表当时就能看见。

把它想成生活里的东西

传统网页开发像装修随时可停业翻新的餐厅；智能合约开发与审计则像建造并检验发射升空的太空舱——升空后极难返厂拆修，一处螺丝松动都可能在高压下造成严重损失。

举个例子（虚构数字，只为讲解）

准备技术作品集可完成一个端到端项目：用 Foundry 编写带时间锁的金库合约，编写单元测试与模糊测试使分支覆盖率超 95%，用 Slither 扫描并记录 Gas 优化对比，部署至测试网并用 React 与 Wagmi 搭建前端公开至 GitHub（仅作示例）。

是谁提出或推广的？

从 2014 年 Solidity 诞生与 2016 年 The DAO 事件到现代合约安全工程

2014 年 Gavin Wood 等人提出面向以太坊虚拟机的 Solidity 智能合约语言。2016 年 6 月，早期知名众筹项目 The DAO 因智能合约重入漏洞（Reentrancy）遭遇重大资金损失，这一历史事件深刻改变了区块链工程界，催生了 OpenZeppelin 标准安全合约库、专业智能合约安全审计行业以及形式化验证与模糊测试工具链的普及。

提出者、推广者和第一个实际使用的人是三回事。这里按可追溯资料写明，不把后来的推广者一律说成最早创始人。

打开后，按这几步看

  1. 选择切入路径：有前后端基础可从 Web3 全栈与数据索引切入，专注底层可攻合约与审计。
  2. 掌握核心工具：EVM 生态重点掌握 Solidity 与 Foundry/Hardhat，非 EVM 生态学习 Rust 或 Move。
  3. 训练防御思维：复现历史漏洞案例，掌握重入、精度误差、预言机操纵与权限缺陷防范。
  4. 构建开源作品：在 GitHub 维护含完整测试、Gas 报告与测试网地址的原创工程。
  5. 参与社区实战：通过黑客松、开源文档贡献或安全夺旗赛（CTF）积累可验证履历。

最容易看错的地方

误区一：照搬模板发币却不写单元测试与边界测试，上线易遭黑客攻击；误区二：轻视前端与数据索引——交易模拟与防钓鱼提示很大程度依赖前后端工程；误区三：误把含真实资金私钥的 .env 文件上传到公开 GitHub 仓库被脚本秒盗。
