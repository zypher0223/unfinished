Web3 技术岗位分为“链上原生”与“Web2.5 融合”两类：前者包括智能合约工程师（用 Solidity、Rust 或 Move 编写协议逻辑，见本站「Smart Contracts & Token Approvals 智能合约与代币授权」一课）、安全审计师（用静态分析、模糊测试与人工审阅排查重入、权限及预言机操纵漏洞）及底层协议与零知识证明（ZK）工程师；后者包括 Web3 前端工程师（用 Viem、Wagmi 等处理钱包连接与交易状态）及后端与链上数据索引工程师（维护节点调用并解析链上事件日志）。因合约部署后难篡改且直接掌管资金池，工程上极度强调测试覆盖率、Gas 优化与防御性编程。

English introduction

Technical roles in Web3 fall into two main tracks: on-chain native roles and Web2.5 integration roles. On-chain native roles include Smart Contract Engineers (writing and optimizing protocol logic in Solidity, Rust, or Move; see the "Smart Contracts & Token Approvals" lesson on this site), Security Auditors (using static analysis, fuzzing, and manual review to uncover reentrancy, access-control, and oracle-manipulation flaws), and Core Protocol / Zero-Knowledge (ZK) Engineers. Web2.5 integration roles include Web3 Frontend Engineers (integrating wallet connections, transaction lifecycle states, and signature prompts via libraries like Viem and Wagmi) and Backend / Indexing Engineers (managing RPC pipelines, indexing on-chain event logs, and serving low-latency APIs). Because deployed smart contracts handle live assets and are often immutable, Web3 engineering places extraordinary emphasis on adversarial thinking, test coverage, and gas optimization.

提出者与来源

从 2014 年 Solidity 诞生与 2016 年 The DAO 事件到现代合约安全工程 — 2014 年 Gavin Wood 等人提出面向以太坊虚拟机的 Solidity 智能合约语言。2016 年 6 月，早期知名众筹项目 The DAO 因智能合约重入漏洞（Reentrancy）遭遇重大资金损失，这一历史事件深刻改变了区块链工程界，催生了 OpenZeppelin 标准安全合约库、专业智能合约安全审计行业以及形式化验证与模糊测试工具链的普及。

Solidity was proposed in 2014 to target the Ethereum Virtual Machine. In June 2016, the high-profile reentrancy exploit of The DAO served as a watershed moment for blockchain engineering, catalyzing the creation of standardized libraries like OpenZeppelin, the professional smart contract auditing industry, and modern fuzzing and static-analysis toolchains.
